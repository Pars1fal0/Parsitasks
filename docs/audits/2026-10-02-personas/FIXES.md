# Исправления после сценарного аудита

Проверки выполняются только в отдельных профилях на искусственных данных.
Личный аккаунт, production, питание и portable не изменяются.
Существующие изменения синхронизации настроек сохраняются.

- [x] P0: подтверждение закрытия формы помещается на узком экране.
- [x] P1: незавершённые показывают категорию, приоритет и отдельный срок.
- [x] P1: массовый перенос повторов объясняет последствия и предлагает одно актуальное действие вместо копий.
- [x] P1: одинаковые ограничения названия в быстром вводе, обычной форме и ДЗ.

- [x] Дополнительно найденная P1: цели не сообщают об успехе при отказе записи; сохранение, этапы, пауза, архив и удаление откатываются.
- [x] Проверить основные сценарии, сохранение, отмену и граничные случаи.
- [x] Выполнить модульные тесты, lint, веб-сборку и браузерные проверки.

## Доказательства

Исходные воспроизведения: `REPORT.md`, `observations.json`, `screenshots/`.
Повторяемые регрессии сохранены в `tests/persona-regressions-e2e.cjs` и
`tests/persona-regressions.test.cjs`; запуск браузерной проверки: `npm run test:audit`.
Гипотезы H1–H5 не считаются критическими ошибками и не требуют незапрошенного редизайна.

Первичная проверка исправлений: 436 модульных тестов, lint, веб-сборка,
`test:planning`, `test:ux-polish` и новая браузерная регрессия прошли.
У подтверждения на 320 px границы теперь 18–302 px, кнопки 39–281 px,
внутреннего переполнения нет. В незавершённой карточке видны «Здоровье»,
«Сдать 3 окт., 12:00», «Высокий». Название длиной 126 символов дописывается.
Перенос 31 пропуска с выбором одного действия не создаёт копий при наличии
открытого естественного выполнения сегодня; каждый пропуск остаётся в своей
дате невыполненным. Другой выбор создаёт 31 отдельную копию явно.

## Дополнительно найденная ошибка сохранения целей

При искусственном отказе записи `rhythm-day-state-v1` пользователь отмечал
первый из двух этапов. До исправления прогресс становился 50%, появлялось
«Этап выполнен», но в сохранённых данных этап оставался невыполненным.
После исправления интерфейс и данные остаются на 0%, появляется сообщение
об отказе сохранения. Форма создания/редактирования сохраняет введённый текст
для повторной попытки. Удаление, пауза и архив тоже откатываются; после
восстановления записи повторная попытка сохраняет этап и показывает 50%.
Проверены отсутствие ложного успеха, восстановление списка и сохранённых
полей цели. В отказавшем сохранении не остаётся ложного удаления/tombstone.

## Осталось вне критических исправлений

- H1–H5 из исходного отчёта: проверить понятность расписания привычки,
  обнаружимость срока/категории и настроек навигации, два вида времени и
  предупреждение о пересечениях с живыми пользователями.
- Независимая проверка экранным диктором; умеренные замечания axe из исходного
  отчёта не считаются полной проверкой доступности.
- Реальные Auth/RLS, облачная синхронизация и Google-интеграции: нужны отдельные
  тестовые аккаунты. Личный аккаунт не используется.
- Публикация выполняется отдельным этапом; текущая версия подготовлена локально.

Обнаруженные блокирующие и важные проблемы этого аудита исправлены.
Это не сертификат коммерческой готовности и не гарантия отсутствия любых ошибок.
