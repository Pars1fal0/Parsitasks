# Продолжение аудита: сохранение привычек и переносы

Дата: 3 октября 2026. Дата искусственных сценариев зафиксирована на 2 октября.
Личный аккаунт, production и Google Drive для проверок не использовались.
Изменения питания отсутствуют; portable не собиралась. Это продолжение
экспертной сценарной проверки, а не новые отзывы реальных пользователей.

## Выполнено

- [x] Воспроизведены ложные сообщения об успехе при отказе записи привычек.
- [x] Отметка, числовой прогресс, создание и редактирование привычки откатываются.
- [x] Порядок, архивирование, возврат из архива и удаление привычек откатываются.
- [x] Заморозка и снятие заморозки не применяются при ошибке записи.
- [x] Форма привычки и диалог заморозки сохраняют ввод для повторной попытки.
- [x] Ошибка редактора показана рядом с кнопкой, а не только за подложкой формы.
- [x] Изменения таймлайна откатываются: время, длительность, выполнение,
  дублирование, удаление, перенос дня, изменение одного повтора, пропуск и
  остановка серии. Успех возвращается вызывающему коду только после записи.
- [x] Отказ сохранения скрытия просрочки и восстановления повторов тоже
  восстанавливает исходное состояние.
- [x] Перенесённая копия повтора сохраняет учебные и заметочные связи.
- [x] Пропуск, перенесённый на уже выполненное естественное повторение,
  остаётся отдельным невыполненным действием; выполненное не стирается.
- [x] Подтверждения таймлайна не применяют изменения к заменённому пространству.
- [x] Удаление объединённой копии в таймлайне не предлагает вернуть повтор,
  если исходный день не исключён.

## Доказательства

До исправления Chrome с искусственным `QuotaExceededError` показывал
«Привычка отмечена», «Привычка создана», увеличивал числовое значение и
закрывал диалог заморозки. Запись при этом не происходила.
[Исходные наблюдения](save-failure-before.json).

После исправления интерфейс возвращается к сохранённому состоянию; остаётся
сообщение об ошибке. Редактор не теряет название, а заморозка — выбор и причину.
После восстановления записи повторная попытка сохраняется. При следующем
успешном действии прежние неудавшиеся изменения не попадают в данные.

[Проверка исходников](save-failure-after.json) и
[проверка готовой сборки через HTTP](save-failure-built.json).

Сообщение редактора проверено на 320, 390, 599 и 1440 px: переполнения нет.
[Снимок 320 px](screenshots/habit-save-error-320.png) просмотрен вручную.

Модульные регрессии подтвердили первоначальные ошибки: шесть действий
таймлайна возвращали успех при отказе записи; копия повтора теряла предмет;
невыполненное действие исчезало при переносе на уже выполненный день.
После исправления эти случаи проходят без ослабления проверок.

## Следующий этап

1. Проверить понятность настроек повторов и разделения работы/срока с двумя
   живыми пользователями. Синтетические сценарии не измеряют удержание и спрос.
2. Проверить Auth, RLS и реальную облачную синхронизацию на двух отдельных
   тестовых аккаунтах, не на основном аккаунте владельца.
3. Пройти основные формы клавиатурой и экранным диктором; автоматический
   анализ доступности не заменяет эту проверку.
4. Отдельно согласовать публикацию после завершения локальной проверки.

Этот этап уменьшает риски потери данных, но не подтверждает полную
коммерческую готовность и не доказывает отсутствие ошибок в остальных разделах.
