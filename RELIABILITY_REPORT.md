# Отчёт об исправлениях надёжности

Дата: 7 октября 2026 года.

Изменения проверены для выпуска 0.34.19. Три SQL-миграции применены в production
7 октября после отдельного подтверждения владельца; проверка готовности базы
прошла. Отдельного staging нет, реальные проверки конкуренции остаются открытыми.
Ни один личный аккаунт не использовался для удаления, перезаписи или
разрушительных тестов. Публикация клиента проверяется отдельно по манифесту.

## 1. Ошибки сохранения и потеря текста

Исправлено:
- Изменения доски и перенос повторяющихся задач откатываются, если локальная
  запись не удалась. Ошибка больше не заменяется уведомлением об успехе.
- Неуспешная запись не запускает облачную отправку и обновление напоминаний.
- Текст доски сохраняется отдельным черновиком текущей вкладки и аккаунта.
  После перезагрузки его можно восстановить и сохранить повторно.
- При смене аккаунта отложенное сохранение текста отменяется.
- Отмена и повтор на доске сохраняют историю при отказе записи.

Проверено искусственным отказом Storage, перезагрузкой и повторным сохранением.
Черновик вкладки не заменяет резервную копию: очистка данных браузера удалит его.

## 2. Запись устаревшим клиентом

Подготовлена миграция `database/20261007-write-compatibility.sql`:
- Сервер отклоняет прямую запись с более старой схемой, чем уже сохранённая.
- Версия документа должна согласовываться с версией строки базы.
- Отдельный owner-only RPC восстановления продолжает использовать проверку
  ревизии и не подменяется незащищённой перезаписью.

Проверено в изолированной PostgreSQL/PGlite. Миграция применена в production;
проверка каталога подтверждает включённый триггер.

## 3. Резервная копия проекта

Добавлен `npm run backup:collect`. Инструмент собирает роли, схему приложения,
данные public/Auth/Storage, фактические файлы Storage, SQL-миграции и переданную
оператором конфигурацию провайдера. Файлы имеют контрольные суммы; повторная
инвентаризация обнаруживает изменения Storage во время сбора.

Результат шифруется отдельным паролем. Ключ Google хранится отдельно, в копию
попадает только его отпечаток. Временный открытый экспорт удаляется только после
успешной упаковки; при сбое частичный экспорт остаётся для проверки оператором.

Ограничения: до 64 МиБ исходных данных, приватный каталог вне репозитория,
Supabase CLI/Docker и доступ к базе/Storage. На Windows нужны приватные ACL.
Конфигурация провайдера не выгружается автоматически. Сбор не доказывает
восстановимость: записывается `restoreVerified: false`.

Проверены синтетические выгрузки и побайтовая распаковка файлов. Реальная копия,
внешнее хранилище и учебное восстановление отдельного проекта ещё не выполнены.

## 4. Безопасный выпуск

- `npm run verify:release` запускает проверки из workflow выпуска последовательно
  и останавливается на первой ошибке. Desktop-релиз использует ту же команду.
- CI публикует только сохранённый проверенный артефакт с контрольными суммами.
- Перед публикацией проверяется готовность защит базы: `npm run verify:database`.
- Старый `build:cloudflare` отказывается собирать обходной непроверенный выпуск.

Нужно настроить GitHub-секреты Cloudflare и отключить прежнюю Cloudflare
source-build интеграцию. Скрипты не выдают эти настройки за уже выполненные.

## 5. Производительность локального состояния

Неизменившаяся ревизия больше не требует повторного разбора и сравнения всего
JSON при каждом сохранении. Изменения другой вкладки по-прежнему объединяются;
добавлен тест записи, произошедшей сразу после нашей записи. От 3 МиБ показывается
предупреждение о большом рабочем пространстве.

Важно: целый JSON в синхронном localStorage всё ещё остаётся основной моделью.
Это оптимизация, не переход на IndexedDB и не устранение всех ограничений объёма.

## 6. Неиспользуемые облачные изображения

Подготовлена миграция `database/20261007-image-retention.sql` и клиентская очистка:
- Изображения младше 30 дней не удаляются.
- Защищены ссылки текущего состояния и всех сохраняемых облачных снимков.
- Очистка и загрузка синхронизированы блокировкой строки рабочего пространства.
- Постоянная отметка удаления не позволяет старому клиенту вернуть ссылку
  или загрузить файл повторно по удалённому пути.
- Файлы удаляются Storage API, а не прямым удалением метаданных SQL.
- Неудачное удаление повторяется позднее и не превращает успешную синхронизацию
  в сообщение о её провале.

Лимит: 100 файлов за запуск, не чаще раза в день в активной клиентской сессии.
Для неактивных аккаунтов отдельный серверный планировщик ещё не создан.
Старые JSON-копии не гарантируют сохранность бинарных изображений. Облачная
очистка не заменяет отдельную локальную очистку кеша, описанную ниже.

Проверены SQL-сценарии ссылок, снимков и устаревших записей. Миграция применена
в production; проверка конкуренции на настоящем managed Storage ещё нужна.

## 7. Реальная инфраструктура и несколько устройств

Добавлены и расширены изолированные SQL/browser-тесты разделения аккаунтов,
офлайн-объединения, восстановления, ошибок квоты и переключения пользователя.
Проверки реального провайдера нельзя считать пройденными по результатам моков.

Остаются staging с двумя выбранными одноразовыми аккаунтами, конкурирующие
загрузки/удаления Storage, реальные устройства и учебное восстановление.

## 8. Вход, CAPTCHA и почта

Добавлена поддержка Turnstile при входе, регистрации и восстановлении пароля.
Без настройки сторонний код не загружается. При включённой настройке отсутствие
или истечение токена блокирует запрос; доступны повторная проверка и сброс.
CSP допускает challenge только на странице авторизации, не во всём приложении.

Проверены мобильная/настольная форма, передача токена и его сброс с моками HTTP.
Нужно выбрать SMTP, настроить DNS отправителя, ключи Turnstile, enforcement
Supabase и проверку утёкших паролей; проверить доставку настоящих писем.

## 9. Мониторинг

GitHub-проверка назначена каждые пять минут. Добавлен независимый от GitHub
`npm run monitor:public`: повторная проверка сбоя, уведомления только при смене
состояния, повтор отправки после ошибки доставки и отдельное тестовое сообщение.
Уведомления не содержат задачи, аккаунты или секреты провайдеров.

Проверены синтетические сбои, восстановление, дедупликация и отказ webhook.
Независимый хост, планировщик и канал ещё не настроены; реальная доставка
уведомления владельцу не подтверждена.

- Названия элементов для скринридеров соответствуют видимым подписям календаря,
  таймлайна, учёбы и навигации.
- Уточнены устаревшие селекторы тестов и ожидание готовности редактора; проверки

## Продолжение: локальные данные и кеш

Резервные копии:
- Автоматические и предимпортные копии получают владельца. Копия другого
  аккаунта не предлагается для восстановления и не подставляется при повреждении.
- Старые копии без владельца не удаляются, но автоматически доступны только
  локальному пространству без аккаунта: назначать их авторизованному пользователю
  без подтверждённого происхождения небезопасно.
- Проверка более новой схемы действует также локально. Исходный документ
  сохраняется; запись старым клиентом блокируется, экспорт включает неизвестные
  поля. Более новая копия не восстанавливается поверх повреждённого документа.
- Импорт ограничен 16 МиБ, проверяет версии оболочки и состояния. Импорт и
  восстановление отменяются, если данные изменились во время подтверждения.

Изображения:
- Ключи IndexedDB разделены по провайдеру и аккаунту. Одинаковый идентификатор
  изображения у разных пользователей не приводит к чтению чужого кеша.
- Запоздавшие ответы загрузки/скачивания после смены аккаунта отклоняются.
- Восстанавливаемый облачный кеш очищается по давности и LRU: 64 МиБ,
  200 записей, 30 дней. Старые записи без подтверждённого владельца и локальные
  единственные копии защищены от удаления и могут превышать эти ограничения.
- Успех записи возвращается только после завершения транзакции IndexedDB,
  а не после отдельного запроса. Заблокированное открытие имеет тайм-аут и
  допускает повтор; чтение и обновление времени доступа не воскрешают удалённый кеш.

Веб-сборка:
- Сборка сначала полностью создаётся во временном каталоге. Ошибка компиляции
  или блокировка прежнего каталога не удаляет рабочий результат предыдущей сборки.
- При ошибке установки нового каталога предыдущий возвращается на место.
  Временные пути проверяются перед удалением; ссылки не принимаются.

Проверены реальные транзакции Chromium IndexedDB в изолированном профиле,
переключение владельца во время HTTP-запроса, ошибки установки сборки и
восстановление/экспорт несовместимых локальных данных. Основная модель всё ещё
синхронный localStorage; интерфейс показывает известную часть новых данных,
но это не полноценный режим чтения с отключением всех кнопок редактирования.
